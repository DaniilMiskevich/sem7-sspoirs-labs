# Лабораторная работа 7 — MPI: парная коммуникация, неблокирующие операции

Распределённое умножение матриц на MPI с использованием **парных (point-to-point)**
операций. Два варианта: блокирующий (`Send`/`Recv`) и неблокирующий (`Isend`/`Irecv`).
Замеряется время каждого варианта.

## Ответы на контрольные вопросы

1. **`MPI_Comm_World`** — communicator по умолчанию: содержит **все** процессы, запущенные
   `mpirun` (каждому процессу доступен один и тот же объект; в mpi4py это `MPI.COMM_WORLD`).
2. **`rank`** — уникальный номер (индекс) процесса внутри communicator, `0 … size-1`.
   В коде: `comm.Get_rank()` и `comm.Get_size()`.
3. MPI-программа **начинается** с `MPI_Init()` и **заканчивается** с `MPI_Finalize()`.
   В mpi4py оба вызова выполняются автоматически при импорте/выходе, но вся логика
   (rank, communicator) от этого контракта зависит.
4. **Преимущество асинхронных (неблокирующих) операций:** `Isend`/`Irecv` не блокируют
   процесс — MPI пересылает данные в фоновых потоках. Пока идёт передача «следующего»
   блока, основной поток уже считает «текущий» частичный результат. Перекрытие
   (overlap) коммуникации и вычислений прячет задержку сети под работой CPU — аналог
   CUDA-стримов, где `cudaMemcpyAsync` пересекается с вычислительными kernel'ами.
   Итог: `T_nonblocking ≈ P·max(T_compute, T_comm)` против `T_blocking ≈ P·(T_compute + T_comm)`.

## Как устроено

- `A` делится на блоки **строк** (по одному на rank), `B` — на **колонки**-полосы
  (по одной на rank). Каждый rank кольцом (ring) обменивается полосами `B`, чтобы
  собрать свою строковую часть `C = A @ B` (`C_rows = A_block @ B_full`).
- Кольцо: каждый шаг rank шлёт свою полосу соседу справа и принимает от соседа слева.
  За `nprocs` шагов каждый rank видит все полосы `B`.
- **Блокирующий** вариант: `Send` → `Recv` → вычисление, строго последовательно
  (без overlap). Ровные rank шлют до приёма, нечётные принимают до отправки — чтобы
  разорвать циклическую зависимость и избежать deadlock.
- **Неблокирующий** вариант: `Isend`/`Irecv` поставлены, **затем** в фоновом потоке
  считается частичный результат, и пока он считается, идёт «передача». Перекрытие
  даёт прирост производительности.

## Зависимости

- Linux (Debian): `sudo apt-get install -y libopenmpi-dev openmpi-bin`
  затем `pip install --break-system-packages mpi4py numpy`.
- Windows: MS-MPI или MPICH + `pip install mpi4py numpy` (mpirun из PATH).

Код переносим на GNU/Linux и Windows (чистый Python + mpi4py + numpy).

## Запуск

```bash
# минимум 3 процесса; размер подбирается под ~10 c (по умолчанию 3000)
mpirun -n $(nproc) ./main.py --size 3000
```
Флаги:
- `--size N` — размер `N x N` (должен делиться на число rank).
- `--seed` — сид для воспроизводимости.
- `--output-dir DIR` — куда писать `rank_i.npy` (частичные результаты).

### Запуск на нескольких хостах в локальной сети

Для запуска распределённых вычислений на нескольких узлах (компьютерах) по локальной сети через Open MPI:

1. **Установка зависимостей на всех хостах:**
   - Установите Open MPI и SSH-сервер (на Debian/Ubuntu):
     ```bash
     sudo apt-get update && sudo apt-get install -y libopenmpi-dev openmpi-bin openssh-server
     ```
   - Установите Python-библиотеки:
     ```bash
     pip install mpi4py numpy
     ```
   - Убедитесь, что проект находится по **одинаковому пути** на всех узлах.

2. **Настройка SSH без пароля:**
   - Настройте авторизацию по ключам так, чтобы главный узел мог подключаться к остальным (и к самому себе) без ввода пароля:
     ```bash
     ssh-copy-id username@host_ip
     ```

3. **Создание файла хостов (`hosts.txt`):**
   Создайте текстовый файл, описывающий узлы и количество процессов (слотов) на каждом:
   ```text
   192.168.1.50 slots=4
   192.168.1.51 slots=4
   ```

4. **Запуск:**
   ```bash
   mpirun --hostfile hosts.txt -n 8 ./main.py --size 3000
   ```
   *(Общее число процессов `-n` должно совпадать с суммой слотов в `hosts.txt`, а `--size` должен делиться на `-n`).*

## Тесты

```bash
# корректность (сравнение с A @ B) + speedup > 1.0
./tests/test.sh
```

`tests/verify.py` восстанавливает полные `A` и `B` из тех же seed и проверяет,
что собранные из `rank_i.npy` результаты равны `A @ B`.
